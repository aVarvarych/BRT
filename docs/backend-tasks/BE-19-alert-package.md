# BE-19 · Пакет попереджень, версія, `304`

**Епік:** 5 · Попередження · **Тип:** історія · **Оцінка:** M · **Залежить від:** BE-18

## Навіщо
Перед стартом поїздки телефон завантажує готовий набір проблем і кешує його. Далі лише реагує, тож попередження працюють навіть без зв'язку (PRODUCT.md §6.1, §6.4).

## Контракт
`GET /v1/routes/:id/alert-package` (необов'язковий заголовок `If-None-Match`)

`200` + заголовок `ETag: "<version>"`:
```json
{
  "routeId": "uuid",
  "version": "string",
  "generatedAt": 1760000000000,
  "problems": [{ "id": "uuid", "lat": 50.1, "lng": 30.1, "type": "pothole", "severity": "serious", "kmFromStart": 34.2 }],
  "sections": [{
    "id": "sec-…", "problemIds": ["…"], "startKm": 40.1, "endKm": 41.3, "lengthM": 1200,
    "worstSeverity": "dangerous", "types": ["pothole", "broken"],
    "polyline": [[50.1, 30.1], [50.2, 30.2]]
  }]
}
```
Якщо `If-None-Match` збігається з поточною версією → `304` без тіла.

## Що зробити
- Юзкейс `GetAlertPackage`: активні проблеми маршруту + лінія → `SectionClusterer` → DTO.
- `version` змінюється за **будь-якої** зміни, що впливає на пакет: нова проблема, зміна типу чи серйозності, «Вже нема», лінія маршруту. Варіанти:
  - (a) хеш від `max(updatedAt)` проблем, їхньої кількості та `route.updatedAt`;
  - (b) лічильник `alert_version` у маршруті, який збільшується в кожному юзкейсі, що змінює проблеми.

  Оберіть один і обґрунтуйте у PR.
- Усунені проблеми в пакет не потрапляють.

## Критерії приймання
- [ ] Integration:
  - пакет містить точкові проблеми й ділянки;
  - повторний запит з `If-None-Match` → `304`;
  - після «Вже нема» версія змінилася й проблеми в пакеті немає.
- [ ] Порожній маршрут → `200` з порожніми масивами.

## Підказки ментора
- Варіант (a) ламається, якщо видалити проблему з найбільшим `updatedAt`: максимум зменшується, але кількість теж змінюється, тож хеш однаково зміниться. Перевірте це тестом. Варіант (b) явніший, але його легко забути збільшити в новому юзкейсі.
