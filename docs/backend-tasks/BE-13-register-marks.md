# BE-13 · Реєстрація позначок і `ProblemMatcher`

**Епік:** 4 · Проблеми · **Тип:** історія · **Оцінка:** L · **Залежить від:** BE-11, BE-12

## Навіщо
Повторна позначка тієї самої ями має підтверджувати проблему, а не створювати нову (PRODUCT.md §3.3, §10.3).

## Що зробити
- Доменний сервіс `ProblemMatcher` з методом `findMatch(position, candidates): Problem | null`:
  - повертає найближчу проблему (активну **або** усунену) у радіусі `matchRadiusM`;
  - використовує `IGeoCalculator`, з базою не працює.
- Таблиці:
  - `problems`:
    - `route_id ... on delete cascade`;
    - `position geometry(Point, 4326)` з **GiST-індексом**;
    - решта полів з BE-12.
  - `marks`:
    - `trip_id ... on delete cascade`;
    - `problem_id references problems on delete set null` (або cascade, на ваш вибір; обґрунтуйте у PR).
- Репозиторій: `findCandidatesNear(routeId, position, radiusM)` повертає лише кандидатів поблизу через `ST_DWithin(position::geography, ..., radius)`. Остаточне рішення, з якою проблемою збіг, ухвалює доменний сервіс.
- `IngestSyncBatch` (BE-11) для кожної позначки:
  1. Позначку з таким `id` вже зареєстровано → пропустити (ідемпотентність на рівні позначки).
  2. Узяти кандидатів, викликати `ProblemMatcher`.
  3. Збіг є → `confirm`. Збігу немає → `Problem.reportNew`.
  4. Зберегти `Mark` з посиланням на `problemId`.
- Поки що `position = rawPosition`. Поправку на реакцію додасть BE-14.
- Відповідь пакета:
  ```json
  "marks": [{ "markId": "…", "problemId": "…", "outcome": "created | confirmed | reactivated" }]
  ```
- `IRouteStatsQuery` (BE-09) тепер рахує `activeProblems`.

## Критерії приймання
- [ ] Unit-тести `ProblemMatcher`:
  - 29 м → збіг, 31 м → немає;
  - з двох кандидатів обирається найближчий;
  - усунена проблема теж підходить для збігу.
- [ ] Integration: два пакети з позначками на відстані 10 м один від одного дають одну проблему з `confirmations = 2`.
- [ ] Integration: дві позначки **в одному пакеті** поруч дають одну проблему. Друга позначка має бачити проблему, створену першою, тому обробляйте позначки послідовно.

## Підказки ментора
- `ST_DWithin` з `::geography` рахує в метрах і використовує GiST-індекс, якщо індекс теж побудований на `geography`, або якщо робити приблизний bbox-фільтр. Перевірте `EXPLAIN` і оберіть варіант. Для одного користувача різниці не відчуєте, але звичку варто виробити.
