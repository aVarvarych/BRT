# BE-11 · Прийом пакетів: точки треку, ідемпотентність

**Епік:** 3 · Синхронізація · **Тип:** історія · **Оцінка:** L · **Залежить від:** BE-10

## Навіщо
Це головний канал даних з телефона. Він має витримувати повтори, запізнілі пакети й погане покриття (PRODUCT.md §6.4, §10.3).

## Контракт
`POST /v1/sync/batches`
```json
{
  "batchId": "uuid",
  "tripId": "uuid",
  "points": [{ "t": 1760000000000, "lat": 50.45, "lng": 30.52, "accuracyM": 6, "speedMps": 24.1, "headingDeg": 182 }],
  "marks":  [{ "id": "uuid", "t": 1760000001500, "lat": 50.45, "lng": 30.52 }]
}
```
Відповідь `200`:
```json
{ "batchId": "uuid", "duplicate": false, "acceptedPoints": 180, "marks": [] }
```
У цій задачі поле `marks` у відповіді лишається порожнім масивом, позначки обробить BE-13.

Обмеження: до 1000 точок і до 50 позначок у пакеті, інакше `400`. `speedMps` і `headingDeg` можуть бути `null`.

## Що зробити
- Таблиці:
  - `track_points`:
    - `trip_id ... on delete cascade`;
    - `t bigint`, `position geometry(Point, 4326)`;
    - `accuracy_m`, `speed_mps`, `heading_deg`;
    - `unique (trip_id, t)`.
  - `sync_batches`:
    - `batch_id pk`, `device_id`, `trip_id`;
    - `received_at`;
    - `points_count`, `marks_count`.
- Юзкейс `IngestSyncBatch`, **усе в одній транзакції**:
  1. `batchId` вже є → повернути `duplicate: true`, нічого не змінювати.
  2. Поїздка існує й належить пристрою, інакше 404.
  3. Вставити точки одним запитом з `ON CONFLICT (trip_id, t) DO NOTHING`.
  4. Оновити `distanceM` і `pointsCount` поїздки (рахувати лише нові точки, див. підказки).
  5. Записати пакет у `sync_batches`.
- ⚠️ **Пакет для вже завершеної поїздки приймається.** Черга на телефоні наздоганяє із запізненням.
- Порт `IGeoCalculator` в domain з методом `distance(a, b)`, реалізація haversine в infrastructure. Цей порт знадобиться в BE-13…BE-18.

## Критерії приймання
- [ ] Повторна відправка того самого `batchId` → `duplicate: true`, кількість точок у базі не змінюється.
- [ ] Два різні пакети з точками, що перетинаються за `t`, не створюють дублів.
- [ ] Пакет для завершеної поїздки → 200.
- [ ] Пакет із 1001 точкою → 400.
- [ ] Якщо вставка точок впала, `sync_batches` не містить запису (транзакція відкотилася).

## Підказки ментора
- Пакети можуть приходити не за порядком. Відстань найпростіше перераховувати по всіх точках поїздки, відсортованих за `t`. Для однієї поїздки (~10 тис. точок) це дешево. Оптимізувати будемо, коли знадобиться.
- Подумайте, що станеться, якщо два однакові пакети прийдуть **одночасно**. Первинний ключ `sync_batches` разом із транзакцією зупинить другий. Обробіть цю помилку як `duplicate: true`.
