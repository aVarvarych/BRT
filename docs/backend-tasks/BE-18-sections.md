# BE-18 · Розбиті ділянки (`SectionClusterer`)

**Епік:** 5 · Попередження · **Тип:** історія · **Оцінка:** L · **Залежить від:** BE-17

## Навіщо
На розбитому відрізку 2 км 20 позначок перетворилися б на 20 сигналів підряд. Тому сусідні проблеми групуються в одну ділянку (PRODUCT.md §3.6, §10.2).

## Що зробити
- Доменний сервіс `SectionClusterer` з методом `cluster(problems, line): { points: Problem[]; sections: Section[] }`. Він працює лише з активними проблемами, у яких є `kmFromStart`:
  1. Відсортувати проблеми за `kmFromStart`.
  2. Сусідні проблеми з різницею `< sectionGapM` (200 м) належать до однієї групи.
  3. Група з ≥ 2 проблем стає ділянкою. Одинока проблема лишається точковою.
  4. Проблеми без `kmFromStart` (не на маршруті) завжди точкові.
- Value object `Section`:
  - `id`: детермінований, наприклад `sec-<id першої проблеми>`;
  - `problemIds`;
  - `startKm`, `endKm`, `lengthM`;
  - `worstSeverity`: найгірша серед проблем групи;
  - `types`: унікальні типи;
  - `polyline`: відрізок лінії маршруту між `startKm` і `endKm`, з точками через `sectionPolylineStepM` (20 м).
- Метод `LinearReferencer.slice(line, fromM, toM, stepM)` вирізає `polyline`.

## Критерії приймання
- [ ] Unit-тести:
  - три проблеми через 150 м → одна ділянка довжиною 300 м;
  - проміжок 250 м → дві окремі точкові проблеми;
  - `worstSeverity` обирається правильно;
  - проблема поза маршрутом точкова;
  - `polyline` починається й закінчується в межах ділянки.

## Підказки ментора
- Ділянка нульової довжини (дві позначки на одному місці) неможлива, бо їх уже злив `ProblemMatcher`. Проте краще захиститися: якщо `lengthM < 1`, хай буде точкова проблема.
