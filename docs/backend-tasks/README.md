## Загальні правила (діють у кожній задачі)

### Архітектура
- Шари `domain` → `application` → `infrastructure` / `presentation`, залежності спрямовані **лише всередину**.
- Аліаси імпортів: `@domain/*`, `@application/*`, `@infrastructure/*`, `@presentation/*`.
- **`domain`** нічого не імпортує з Express, Drizzle чи `pg`. Там лише TypeScript, правила й інтерфейси (порти).
- **`application`**: юзкейси. Один клас на дію з методом `execute(input)`, залежності надходять через конструктор.
- **`infrastructure`**: Drizzle-репозиторії, гео-обчислення, годинник, генерація id.
- **`presentation`**: Express-роутери, валідація вхідних даних, мапінг DTO.
- Усі конкретні класи створюються в **одному** місці: `src/main/compositionRoot.ts`. Контейнер залежностей не використовуємо.
- Час береться лише через порт `Clock`, а не через `Date.now()` у домені чи юзкейсах, щоб тести були детермінованими.

### Контракт API (спільне для всіх ендпоінтів)
- Префікс `/v1`, тіло запиту й відповіді в JSON.
- Заголовки в кожному запиті, крім `/health`:
  - `X-Api-Key`;
  - `X-Device-Id` (UUID).
- Усі `id` — UUID, які генерує **клієнт**.
- Час завжди передається числом: мілісекунди від epoch (як `Date.now()` у JS).
- Формат помилки:
  ```json
  { "error": { "code": "ROUTE_NOT_FOUND", "message": "Маршрут не знайдено", "details": {} } }
  ```
- Коди відповідей:
  - `400` — невалідні дані;
  - `401` — немає ключа або ключ неправильний;
  - `404` — ресурс не існує **або належить іншому пристрою** (тоді не видаємо, що він існує);
  - `409` — конфлікт;
  - `500` — усе інше, без деталей назовні.
- Повний контракт буде в `docs/api.md` (його складає Claude). До того джерелом правди лишаються ці задачі.
